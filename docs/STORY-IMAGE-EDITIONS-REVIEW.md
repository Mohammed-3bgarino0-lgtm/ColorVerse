# مراجعة محرك نسختي القصة والتلوين

الفرع: `feature/story-studio-integration`

آخر تحديث: 26 يوليو 2026

## القرار المعتمد

ينتج كل كتاب نسختين مستقلتين دائمًا:

1. **نسخة القصة**
   - غلاف وصور ملونة.
   - نص القصة المعتمد من ولي الأمر.
   - الحوارات.
   - سؤال ونهاية وتوقيع المؤلف الصغير.

2. **نسخة التلوين**
   - غلاف مستقل للنسخة.
   - رسمة خطية مطابقة لكل مشهد ملون.
   - الصفحات الداخلية لا تحتوي عنوان مشهد أو نص قصة أو حوار أو شرح أو تعليمات أو رقم صفحة.

لم يعد خيار الإخراج كتابًا مختلطًا. تستبدل الواجهة الخيارات القديمة بحقل ثابت اسمه «نسختان منفصلتان».

## دورة إنتاج الصور

```text
قصة معتمدة من ولي الأمر
  -> مرجع شخصية البطل
  -> غلاف الكتاب
  -> صورة ملونة للمشهد 1
  -> تحويل الصورة نفسها إلى رسمة تلوين صافية
  -> تكرار لكل المشاهد
  -> حفظ الأصول
  -> تفعيل رابط نسخة القصة ورابط نسخة التلوين
```

عدد الأصول في كتاب من 8 مشاهد:

```text
1 شخصية + 1 غلاف + 8 صور قصة + 8 رسومات تلوين = 18 أصلًا
```

## ثبات الشخصية

- صورة الطفل اختيارية وتُرسل فقط عند وجود موافقة محفوظة.
- تُنشأ أولًا صورة مرجعية واحدة للبطل.
- الغلاف وكل صور القصة تستخدم صورة البطل المرجعية.
- صفحة التلوين تُشتق من صورة المشهد الملونة نفسها، وليس من نص مستقل.
- تمنع البرومبتات تغيير الوجه أو الشعر أو الملابس أو الألوان أو الإكسسوارات بين المشاهد.

## حماية نسخة التلوين

يتضمن البرومبت حظرًا صريحًا لـ:

- نص القصة.
- العنوان.
- الشرح.
- الحوار.
- فقاعات الكلام.
- الحروف والأرقام.
- أرقام الصفحات.
- الشعارات والعلامات المائية.

كما يفحص اختبار آلي أن دالة PDF الخاصة بالتلوين لا تستخدم `scene.title` أو `scene.storyText` أو الحوارات أو أرقام الصفحات داخل الصفحات الداخلية.

## API الصور

```http
GET    /api/story-images/health
POST   /api/story-images/jobs
GET    /api/story-images/jobs/:jobId
DELETE /api/story-images/jobs/:jobId
```

المهام غير متزامنة وقابلة للإلغاء. الترتيب الافتراضي مهمة واحدة في الوقت نفسه لحماية التكلفة.

## التخزين

التنفيذ الحالي يحفظ الملفات في:

```text
generated-assets/story-images/<book-id>/
```

ويعرضها عبر:

```text
/generated-assets/...
```

طبقة التخزين قابلة للاستبدال، لكن Firebase Storage لم يُربط بعد في هذه المرحلة.

## إعدادات البيئة

```env
GEMINI_API_KEY=
GEMINI_IMAGE_MODEL=gemini-3.1-flash-image
GEMINI_IMAGE_TIMEOUT_MS=120000
GEMINI_IMAGE_MAX_ATTEMPTS=2
IMAGE_JOB_CONCURRENCY=1
IMAGE_RATE_LIMIT_WINDOW_MS=1800000
IMAGE_RATE_LIMIT_MAX=2
GENERATED_ASSET_DIR=./generated-assets
GENERATED_ASSET_PUBLIC_BASE_URL=/generated-assets
```

## واجهة المستخدم

بعد اعتماد ولي الأمر يظهر زر:

```text
إنتاج النسختين الآن
```

ثم تقدم المهمة، وبعد الاكتمال:

```text
فتح نسخة القصة
فتح نسخة التلوين
```

الوضع التجريبي يستخدم صورًا نموذجية بعلامة `productionReady: false`، ولذلك لا يفعّل PDF النهائي.

## PDF

الرابطان:

```text
book-print-ai-review.html?edition=story
book-print-ai-review.html?edition=coloring
```

لكل نسخة:

- PDF مراجعة مستقل.
- PDF نهائي مستقل.
- فحص جاهزية مستقل.

نسخة القصة النهائية تحتاج الغلاف وكل الصور الملونة الإنتاجية. نسخة التلوين النهائية تحتاج الغلاف وكل الرسومات الخطية الإنتاجية.

## فحوص الجودة

```bash
npm run validate:story-images
npm run test:story-images
npm run quality:stories
```

تتحقق الفحوص من:

- إنتاج صورتين لكل مشهد.
- إجبار النظام على نسختين منفصلتين.
- منع الكتابة داخل رسومات التلوين.
- عدم وجود نصوص سردية في صفحات PDF الداخلية للتلوين.
- عدم تفعيل PDF النهائي مع الأصول التجريبية.
- رفض إنتاج الصور قبل موافقة ولي الأمر.

## ما لم يُنفذ أو يُثبت بعد

- لم يُدخل مفتاح Gemini حقيقي.
- لم يُنفذ طلب صور فعلي مدفوع.
- لم تُراجع جودة ثبات وجه طفل حقيقي عبر 8 أو 12 أو 16 مشهدًا.
- لا يوجد فحص بصري آلي لاكتشاف تغير الملابس أو الوجه.
- المهام محفوظة في الذاكرة وتضيع عند إعادة تشغيل الخادم.
- التخزين السحابي وFirebase Storage غير مربوطين.
- لا يوجد استئناف للمهمة من آخر مشهد بعد انقطاع الخادم.
- لم تُدمج المرحلة في `main` ولم تُنشر.

## المرحلة التالية المقترحة

إضافة بوابة مراجعة الصور قبل اعتمادها: عرض صورة البطل والغلاف والمشاهد، السماح بإعادة توليد أصل واحد فقط، فحص تطابق نسخة التلوين مع المشهد، ثم حفظ حالة الموافقة على كل صورة قبل فتح PDF النهائي.
