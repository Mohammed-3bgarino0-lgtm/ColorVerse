# مراجعة ربط الذكاء الاصطناعي بمحرك القصص

الفرع: `feature/story-studio-integration`

آخر تحديث: 26 يوليو 2026

## الهدف

ربط Gemini على الخادم لتحويل فكرة الطفل إلى قصة كاملة بصيغة JSON، ثم رفض أي نتيجة لا تطابق بنية الكتاب أو لا تحافظ على أفكار الطفل أو تقترب أكثر من المسموح من المرجع.

هذه المرحلة لم تُدمج في `main` ولم تُنشر على GitHub Pages.

## مسار الطلب

```text
المتصفح
  -> POST /api/stories/generate
  -> التحقق من بيانات الطفل والقصة
  -> اختيار المرجع اليدوي أو الذكي
  -> بناء الخطة والبرومبت
  -> Gemini على الخادم
  -> التحقق من JSON وعدد المشاهد
  -> فحص الأصالة وحفظ أفكار الطفل
  -> إعادة محاولة تصحيح عند الفشل
  -> إعادة القصة المقبولة فقط إلى الواجهة
```

## الحماية

- مفتاح Gemini موجود على الخادم فقط.
- المتصفح يرسل بيانات القصة إلى `/api/stories/generate` ولا يرى المفتاح.
- التحقق يفرض 8 أو 12 أو 16 مشهدًا بالضبط.
- كل مشهد يحتاج نصًا، حوارًا اختياريًا، وصف رسمة، ووصف صفحة تلوين مطابقة.
- لا يُقبل اسم مرجع مختلف عن المرجع الذي اختاره المحرك.
- لا يُقبل مرجع عند وضع «فكرة حرة» أو «تحسين قصة الطفل».
- فشل الأصالة يطلق محاولة تصحيح ثانية تلقائيًا.
- الحد الأقصى للمحاولات ثلاث، والافتراضي محاولتان.
- يوجد حد استخدام أولي لكل عنوان شبكة لحماية تكلفة API.
- الأخطاء العامة لا تكشف البرومبت أو مفتاح API.

## إعدادات البيئة

```env
GEMINI_API_KEY=
GEMINI_STORY_MODEL=gemini-2.5-flash
GEMINI_STORY_TIMEOUT_MS=90000
GEMINI_STORY_MAX_ATTEMPTS=2
STORY_RATE_LIMIT_WINDOW_MS=600000
STORY_RATE_LIMIT_MAX=6
```

يجب اختيار اسم النموذج من إعداد الخادم، لذلك يمكن تغييره مستقبلًا دون تعديل الكود.

## نقطة API

### فحص الحالة

```http
GET /api/stories/health
```

لا يعرض المفتاح، ويعيد فقط هل المحرك مضبوط واسم النموذج المستخدم.

### إنشاء قصة

```http
POST /api/stories/generate
Content-Type: application/json
```

مثال:

```json
{
  "childName": "ليان",
  "childAge": 8,
  "heroName": "ليان",
  "childStory": "ليان وجدت نجمة زرقاء وأرادت إعادتها إلى السماء.",
  "adventure": "رحلة فضائية عن التعاون والأمانة",
  "moral": "التعاون والأمانة",
  "helperCharacter": "روبوت مرح",
  "templateLabel": "الفضاء",
  "pageCount": 8,
  "language": "ar",
  "referenceMode": "none"
}
```

أوضاع المرجع:

- `none`
- `child_story`
- `selected_reference`
- `auto_reference`

## حالات الاستجابة

- `201`: قصة مقبولة.
- `400`: بيانات الطلب غير صحيحة.
- `422`: النتيجة لم تجتز الأصالة بعد محاولات التصحيح.
- `429`: تجاوز الحد المؤقت.
- `502`: تعذر الاتصال بالمزود أو إنتاج نتيجة صالحة.
- `503`: مفتاح Gemini غير مضبوط.

## فحوص دون استهلاك Gemini

```bash
npm run validate:stories
npm run typecheck:stories
npm run test:story-ai
npm run quality:stories
```

اختبار `test:story-ai` يستخدم مزودًا وهميًا، ويتحقق من:

1. رفض عدد مشاهد خاطئ.
2. قبول قصة صحيحة تحافظ على أفكار الطفل.
3. رفض المحاولة الأولى عندما تهمل فكرة الطفل.
4. إرسال تعليمات تصحيح للمحاولة الثانية.
5. قبول المحاولة الثانية بعد التصحيح.

## ملاحظة الاستضافة

GitHub Pages يستضيف ملفات ثابتة فقط، لذلك لن يشغّل `/api/stories/generate`. عند مرحلة التشغيل يجب نشر خادم `server.ts` على خدمة تدعم Node.js، أو فصل الـAPI في خدمة خادم مستقلة، ثم ضبط عنوان الـAPI في عميل المتصفح.

## ما لم يتم بعد

- لم يتم إدخال مفتاح Gemini حقيقي في المستودع.
- لم يتم تنفيذ طلب مدفوع أو فعلي إلى Gemini.
- لم يتم ربط زر الواجهة بعميل `story-ai-client.js` بعد.
- لم يتم تخزين القصة النهائية في Firebase.
- لم يتم توليد الصور والغلاف من المشاهد بعد.
- لم يتم نشر خادم Node.

## المرحلة التالية المقترحة

ربط زر «بناء القصة الاحترافية» بالعميل، وإضافة شاشة تقدم ومراجعة ولي الأمر، مع وضع تجريبي يعمل بالمزود الوهمي قبل تشغيل المفتاح الحقيقي.
