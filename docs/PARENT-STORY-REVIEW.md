# مرحلة مراجعة ولي الأمر — ColorVerse

الفرع: `feature/story-studio-integration`

آخر تحديث: 26 يوليو 2026

## الهدف

بعد أن يكتب الطفل فكرته، لا تنتقل القصة مباشرة إلى الغلاف أو الـPDF. تمر أولًا بهذه الرحلة:

```text
فكرة الطفل
  -> اختيار المرجع المناسب
  -> إنشاء النص بالذكاء الاصطناعي أو الوضع التجريبي
  -> فحص البنية والأصالة
  -> مراجعة ولي الأمر وتعديل النص
  -> موافقة صريحة
  -> المعاينة والغلاف والـPDF
```

## مدخل المراجعة الحالي

تم إنشاء صفحة مستقلة لا تغيّر `create.html` أثناء المراجعة:

```text
create-ai-review.html
```

تفتح الصفحة استوديو الإنشاء نفسه، ثم تحمّل بالترتيب:

1. `public/js/story-studio-runtime.js`
2. `public/js/story-ai-client.js`
3. `public/js/story-parent-review-runtime.js`

بعد اعتماد المرحلة يمكن تطبيق الربط على الصفحة الأساسية بالأمر:

```bash
node scripts/apply-story-studio-integration.mjs create.html
```

الأداة لا تكرر ملفات JavaScript إذا كانت متصلة مسبقًا.

## شاشة التقدم

عند الضغط على «بناء القصة بالذكاء الاصطناعي» تظهر مراحل واضحة:

- حفظ أفكار الطفل.
- اختيار المرجع المناسب.
- كتابة القصة والحوارات.
- فحص الأصالة وحضور أفكار الطفل.
- تجهيز مراجعة ولي الأمر.

لا يظهر النص النهائي قبل اكتمال الطلب أو الانتقال إلى الوضع التجريبي المعلن بوضوح.

## أوضاع التشغيل

### `auto`

الوضع الافتراضي. يحاول الاتصال بـ`/api/stories/generate`. عند غياب خادم Node أو عدم ضبط Gemini ينتقل إلى نموذج تجريبي محلي، مع إظهار تنبيه واضح بأن الفحص النهائي لم يعمل.

### `live`

يستخدم الخادم فقط ولا ينتقل تلقائيًا إلى النموذج التجريبي.

### `demo`

ينشئ قصة تجريبية محليًا من خطة الطفل دون استهلاك Gemini.

يمكن ضبط الوضع من أدوات التطوير:

```js
ColorVerseParentReview.setMode('auto');
ColorVerseParentReview.setMode('live');
ColorVerseParentReview.setMode('demo');
```

وعند فصل الـAPI في نطاق مستقل:

```js
ColorVerseParentReview.setApiBaseUrl('https://api.example.com');
```

## مراجعة ولي الأمر

تعرض الصفحة:

- اسم الطفل بوصفه صاحب الفكرة.
- المرجع المستخدم أو حالة عدم استخدام مرجع.
- عدد المشاهد.
- حالة الأصالة أو تنبيه الوضع التجريبي.
- عنوان القصة القابل للتعديل.
- القيمة التربوية.
- السؤال الختامي.
- عنوان ونص وحوار كل مشهد.
- عداد أحرف لكل مشهد.

لا يمكن اعتماد القصة قبل تحديد مربع الموافقة:

```text
راجعت عنوان القصة ونصوص المشاهد، وأوافق على اعتماد هذه النسخة للكتاب.
```

## البيانات المحفوظة في المسودة

بعد التوليد:

```text
state.generatedStory
state.storyGeneration
state.originalityReport
state.storyPlan
```

بعد موافقة ولي الأمر:

```text
state.parentReview.approved
state.parentReview.approvedAt
state.parentReview.reviewVersion
state.parentReview.sceneCount
```

كما تم توسيع `src/lib/book-schema.ts` ليحتوي نموذج مراجعة ولي الأمر الكامل عند تحويل المسودة إلى كتاب محفوظ.

## الحماية

- مفتاح Gemini لا يرسل إلى المتصفح.
- كل نص قادم من الـAPI يُعرض بعد HTML escaping.
- عدد المشاهد يطابق 8 أو 12 أو 16.
- ولي الأمر يستطيع تعديل النص قبل الاعتماد.
- لا ينتقل المستخدم إلى المعاينة النهائية دون الموافقة.
- الوضع التجريبي معلن ولا يُعرض بوصفه نتيجة فحص أصالة حقيقية.
- القصة المرفوضة بسبب الأصالة لا تظهر بوصفها نسخة معتمدة.

## فحوص المرحلة

```bash
npm run validate:story-review
npm run quality:stories
```

الفحص يتأكد من:

- صحة JavaScript نحويًا.
- وجود عميل الـAPI.
- وجود شاشة التقدم.
- وجود الوضع التجريبي.
- وجود موافقة ولي الأمر.
- حفظ القصة المعتمدة في خطة الكتاب.
- تحميل الملفات بالترتيب الصحيح.

## حالة التنفيذ

- تم تنفيذ الملفات داخل فرع التطوير.
- لم تُدمج في `main`.
- لم تُنشر على GitHub Pages.
- تعذر تشغيل أوامر الجودة محليًا في جلسة التطوير الحالية بسبب عدم توفر اتصال شبكي إلى GitHub.
- لم تظهر حالة فحص GitHub Actions على آخر commit وقت التحقق، لذلك لا يُدعى نجاح CI بعد.

## المرحلة التالية

تحويل القصة المعتمدة إلى صفحات كتاب حقيقية، وربط كل مشهد بوصف الصورة وصفحة التلوين، ثم جعل قالب الـPDF يستخدم `state.generatedStory` بدل خطة المشاهد التجريبية.
